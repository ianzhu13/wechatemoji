# 🎉 WeChatEmoji 🧸✨

> 把微信里的可爱表情一只只请出来，再整整齐齐送去飞书的小工具 🐣💬➡️📦➡️🛫

一个面向 Windows 的微信表情提取与飞书导入工具，适合做个人表情备份、整理和迁移。项目同时提供 GUI 和 CLI 两种使用方式，目标是把“提取表情这件麻烦事”变得更轻松一点。

## 项目来源

本仓库是 [henrytian1998/wechatemoji](https://github.com/henrytian1998/wechatemoji) 的 fork，当前分支维护于 [ianzhu13/wechatemoji](https://github.com/ianzhu13/wechatemoji)。原项目的微信表情提取、飞书导入基础流程、图形界面及 Tauri 工程均来自上游，感谢原作者和贡献者。

本 fork 在上游基础上增加微信 4.1.x 兼容性修复、桌面启动修复和上传排障改动。`Config.Cipher` 密钥提取参考了 [fanyuantaier/wechatauto-replica 的实现](https://github.com/fanyuantaier/wechatauto-replica/blob/main/wechatauto/db.py)。项目许可证见 [LICENSE](LICENSE)。

## 本 fork 做了哪些改动

以下为截至 **2026-10-29** 的改动记录。代码已实现、本地测试通过和真实账号下的完整流程验证，分别列明。

| 模块 | 改动与修复 |
| --- | --- |
| 微信密钥提取 | 增加只读定位 `Config.Cipher` 对象的提取路径，保留旧版 `x'…'` 明文候选扫描回退；补齐 Windows 64 位进程接口声明、分块扫描和部分读取处理。 |
| 密钥验证与解密 | 候选需通过目标库首页验证、全库逐页 HMAC 认证及 SQLite 完整性检查；增加防覆盖原库和验证通过后再替换输出文件的处理。 |
| 安全诊断 | 输出区域读取、格式匹配、目标库关联候选和验证通过数量；不输出真实密钥、完整内存内容或数据库记录。 |
| 微信账号发现 | 通过 `db_storage` 目录识别账号，兼容目录名不以 `wxid_` 开头的账号。 |
| 动画导出 | 无需缩放的 GIF 保留原始字节；需要缩放时保留全部帧、帧时长、透明区域和循环设置；编码异常或输出帧数改变时保留原动画，取消静态首帧回退。动画 PNG / WebP 也保留原始文件。 |
| 桌面启动与按钮 | 将原生窗口引用改为内部属性，避免 pywebview 导出接口时递归遍历窗口对象，导致启动连接卡住、按钮无响应。 |
| 飞书登录等待 | 等待期间处理浏览器事件，避免地址仍停留在登录页；检查实际消息列表或输入区，登录后保留当前租户消息页。 |
| 个人表情导入 | 跳过没有输入框的通知会话，复用已打开的表情面板；自动定位失败时接管同一张图片；文件提交后结果不明时停止批次并显示未尝试数量。 |
| 上传结果与窗口处理 | 不再把聊天正文或旧通知中的“上传成功”作为当前文件的成功依据；个人上传确认按钮限定在对话框内；出错或中断后保留浏览器供检查。 |
| 回归测试 | 新增 55 项本地回归测试，并接入 CI 配置，覆盖密钥验证、动画保留、登录跳转、模拟文件导入、异常中断和桌面接口注册。 |

### 已验证的范围

- **微信提取实机验证**：在 Windows、微信 **4.1.13.65** 上，目标 `emoticon.db` 的密钥提取成功，481 页通过认证和解密完整性检查；测试前后源数据库摘要一致。
- **桌面启动验证**：本机 Windows、pywebview **6.2.1** 的实际桌面窗口测试通过，确认连接初始化、标签切换和按钮调用后台有效。
- **动画重新导出**：已从微信原资源在独立目录重新导出，对比确认旧版单帧 GIF 可恢复为多帧动画；原导出目录文件的摘要保持一致。
- **本地回归**：55 项测试、Python 语法检查和差异检查通过。其中 11 项图像回归覆盖动画帧数、时长、循环、透明区域和异常回退。浏览器回归使用本地拦截的模拟页面，不使用真实账号上传文件。
- **飞书现场结果**：出现过前 2 项经页面列表变化确认、第 3 项未获确认后中断的情况。连续批量导入尚未验证通过，当前应按实验性功能使用。

## 🌈 项目简介

`WeChatEmoji` 是一个面向 Windows 的小工具，帮助你从本机微信客户端里提取自定义表情，并导出为常见图片格式，进一步支持导入飞书个人表情或企业表情包。

整个项目的目标很简单：

- 😺 少一点手工翻目录
- 🪄 少一点重复搬运
- 🎈 多一点“表情终于整理好了”的快乐

## ✨ 能做什么

- 🔍 自动发现本机微信账号与表情数据
- 🔐 提取并解密微信表情资源
- 🖼️ 导出为常见图片格式（PNG / GIF 等）
- 🧰 提供图形界面模式，适合日常使用
- ⌨️ 提供 CLI 模式，方便调试和自动化
- 🚀 提供飞书个人表情导入入口（实验性，批量稳定性待修复）
- 🏢 保留飞书企业表情包导入入口（未完成实机验证）
- 🩺 提供 `audit` 审计命令，帮助检查环境和链路状态

## 🧁 使用场景

- 📦 备份自己的微信收藏表情

## 🛠️ 环境要求

- Windows 系统
- 本机已安装并登录微信
- 提取时建议微信客户端处于运行状态
- Python 3.11+（源码运行时，数据库完整性验证需要 `sqlite3.deserialize`）

## 🚀 安装

### 1. 安装 Python 依赖

```bash
pip install -r requirements.txt
```

### 2. 安装 Playwright Chromium

如果你需要使用飞书导入能力，请继续安装：

```bash
python -m playwright install chromium
```

## 🎮 使用方式

### 图形界面模式（推荐）🐥

```bash
python main.py
```

适合大多数同学，点一点就能完成提取、预览和导入。

### 命令行模式 ⌨️

```bash
# 提取微信表情
python main.py --cli extract

# 提取指定微信账号的表情
python main.py --cli extract --wxid <wxid>

# 上传到飞书个人表情
python main.py --cli upload --mode personal

# 上传到飞书企业表情包
python main.py --cli upload --mode enterprise --pack-name "我的表情包"

# 先提取，再继续导入飞书
python main.py --cli full --mode personal

# 检查提取链路和上传环境
python main.py --cli audit
```

## 📦 导出与数据目录

密钥提取优先只读定位 WCDB `Config.Cipher`，保留旧版 `x'…'` 内存候选回退。
候选必须通过目标库逐页 HMAC、解密后的 SQLite 头检查和 `PRAGMA integrity_check`。
仅诊断提取链路时可运行（不会保存密钥、明文库或进程内存转储）：

```powershell
python key_extractor.py "<账号目录>\db_storage\emoticon\emoticon.db" --diagnose
```

日志只包含阶段信息和计数：`regions_read` 为成功读取的去重区域数，`legacy_matches` /
`cipher_matches` 为两种格式匹配数，`target_candidates` 为 salt 匹配或首页验证关联的去重候选数，
`page1_verified` / `integrity_verified` 为首页验证和全库完整验证通过数。salt 关联本身不表示成功。
`bytes_read` 累计各轮扫描；`read_failures` / `partial_reads` 记录失败或部分成功的读取调用。
Config.Cipher 对象偏移与掩码依赖微信版本；当前页面格式限定为 SQLCipher 4、4096 字节页、
80 字节保留区和加密文件头。需要 64 位 Python，以及读取微信进程的权限。
只验证主数据库文件，不合并 WAL；微信正在写入时完整性验证可能失败，可在空闲时重试。

离线回归测试：`python -m unittest discover -s tests -v`（只使用合成夹具）。
登录跳转的浏览器回归需要已安装 Playwright Chromium，否则会跳过；测试页面在本地拦截，
不会登录真实账号或上传文件。

若扫码后只有头像和灰色占位，说明消息列表还未加载完成；工具会等待实际会话项或聊天输入区可见后继续。
更新代码后请关闭旧程序及其打开的浏览器，再运行 `python main.py`，已导出的表情可以继续使用。

个人表情导入会跳过无输入框的通知会话，并复用已打开的自定义表情面板。
自动定位失败时，手动打开一次「表情 → 自定义 → 添加」即可由工具接管同一张图片。
文件提交后结果未确认时会停止本批，不重复提交；界面分别显示成功、失败或未确认、未尝试数量。
登录超时、上传出错或中断时，飞书浏览器会保留供检查；关闭该浏览器窗口或点击「停止上传」后，
工具才会清理浏览器并允许开始下一次导入。窗口保留期间不会继续提交文件。
上传确认只读取可见通知和自定义表情列表变化，聊天正文中的“上传成功”不作为上传证据。

为了避免把运行状态写到 `exe` 同级目录，项目默认会把用户可写数据放到本机用户目录下。

- 表情导出目录：`%LOCALAPPDATA%\wechatemoji\output\emojis`
- 调试信息目录：`%LOCALAPPDATA%\wechatemoji\output\debug`
- 临时文件目录：`%LOCALAPPDATA%\wechatemoji\output\tmp`

### 重新导出旧版已丢帧的 GIF

旧版会将部分动图保存成单帧。更新代码不会自动恢复旧文件中已丢失的帧，需要从微信原资源重新导出。
请在工具中将导出目录切换到一个新目录，再点击「开始导出」；原目录中的文件会保留。
同一目录再次导出会跳过已有同名文件，因此仅点击原目录的「开始导出」不能修复旧单帧文件。
工具预览列表使用静态缩略图，判断动画是否恢复请打开导出的原始 GIF，或检查文件帧数。

## 🏗️ 打包 EXE

项目已经准备好了打包脚本：

```bash
build.bat
```

这个脚本会完成以下动作：

- 🎬 检查并整理 Playwright Chromium runtime
- 🧹 清理正在运行的旧版程序
- 📦 使用 PyInstaller 打包
- ✅ 校验 `wechatemoji.exe` 和前端资源是否正确输出

打包后的主程序通常位于：

```text
dist\wechatemoji\wechatemoji.exe
```

## 🧠 工作原理

1. 🕵️ 定位微信数据目录与表情数据库
2. 🔑 提取数据库解密所需信息
3. 🧩 读取并整理表情记录
4. 🖼️ 还原导出为可直接查看/上传的图片文件
5. 🚀 按需导入飞书个人表情或企业表情包

## ⚠️ 注意事项

- 仅建议用于个人数据整理、备份与迁移 🌿

- 企业表情包上传请遵循所在组织的规范要求 🏢
- 如果你是从源码运行，请先确认 Playwright Chromium 已安装完成 🛠️
